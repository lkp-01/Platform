# Trace 第一版实施计划

**Goal:** 开发者打开一个 Run，即可查看持久化的 Model Call、Tool Call、Tool Result、Final Answer、错误及基础指标，定位任务内部发生了什么。

**Architecture:** Harness Session 日志和已有 Run 生命周期记录继续作为执行事实来源；Platform 通过插件补充缺失的调用边界，并生成可重建的 Trace 查询投影。Run 管任务状态，Trace 管执行事实与指标，Harness 保持唯一 Agent Loop。

**Tech Stack:** 现有 TypeScript、Cordis、Session Events、Storage Domain、Typert Remote、React、Vitest 和 Web E2E。

**状态：** 2026-09-17 已实施，结果见 [Trace 验收记录](../trace-acceptance.md)。沿用当前单 Host、一个 Run 对应一个独立 Session 的范围。下文保留原计划，具体实现差异以验收记录为准。

**实施调整：** Session.append 不支持设置 ignorable 标记，因此模型起点通过现有 Agent 通知保存到平台 Trace Domain，并记录相邻 Session 序号；无需修改 Harness 核心。查询投影采用合并通知后的确定性源日志对账与版本化页面，暂不增加持久化增量状态 Schema；普通查询读取已保存页面，长 Run 的重复源日志折叠成本在验收记录中说明。

## 1. 本期范围与方案

第一版在现有 Run 详情中增加 Trace 时间线与统计摘要，不建立独立观测平台。包含模型调用及已有模型重试事实、工具调用与结果、最终答案、错误、调用耗时、Token 和总调用次数。记录可展开的参数、结果摘要及原始事件引用。

不包含复杂 span 树、分布式 tracing、日志检索、指标大盘、告警、成本计费、新的执行重试机制、子 Agent 跨 Session 聚合，以及自动判断答案为什么错误。Trace 提供排查证据，不承诺判断模型内部推理原因。

推荐采用“原始事件 + 持久化查询投影”。只在缺少事实时通过插件补记，不重新采集一套完整对话。

| 方案 | 优点 | 代价与结论 |
|---|---|---|
| 原始事件 + 持久化查询投影 | 可增量查询、重启恢复、统一指标口径，后续 Evaluation 能复用 | 增加小型投影器和持久化模块；推荐 |
| 每次打开详情扫描完整 Session | 实现较少、没有新增查询存储 | 长日志反复扫描，补齐调用起点仍需插件；适合作为投影重建路径 |
| 独立 OTel / Trace 服务 | 适合后续跨服务观测 | 当前引入部署与数据一致性复杂度，不采用 |

## 3. 事件与关联设计

产品上一个 Run 对应一条 Trace，第一版直接以 runId 查询，不另建一套 Trace 生命周期。

公共字段：`eventId`、`runId`、`sessionId`、`agentId`、`agentVersionId`、`platformWorkspaceId`、`type`、`occurredAt`、稳定排序键、`sourceRefs`、可选 `turn/step/operationId` 和按事件类型区分的 payload。使用现有 branded ID 习惯，存储记录带 schema 版本。

`sourceRefs` 可以引用 Session 序号或 Run 生命周期 eventId。事件 ID 从源记录和事件类型确定性生成；相同源事件重复投影不会重复插入。不要用毫秒时间戳充当唯一 ID。工具用原始 callId 加 Session/turn/step 关联；模型调用使用持久化开始事件的序号关联，不能把仅进程内唯一的 attemptId 当成跨重启 ID。

| 事件 | 内容与来源 |
|---|---|
| `run.created` / `run.started` | 沿用 Run 已保存的事件 |
| `model.call.started` | 实际 provider/model、turn/step、调用标识、起始时间；插件补记 |
| `model.call.completed` | assistant/message 的输出引用、finish reason、usage、耗时；成功的模型调用不等于 Run 成功 |
| `model.call.failed` / `model.call.cancelled` | assistant/attempt、stream finish、interrupted 标记与结束原因；未知原因保持未知 |
| `model.retry.scheduled` | 现有重试错误、次数和等待时间；只有再次开始才算下一次调用 |
| `tool.call.started` | tool 名、callId、原始 arguments，保留无法解析的 JSON 文本 |
| `tool.call.completed` / `tool.call.failed` | tool/result 的内容引用、isError、错误 code 和调用耗时 |
| `final.answer` | 根据 Run 成功结果的 finalMessageSeq 引用最终文本；无文本则不伪造答案事件 |
| `run.succeeded` / `run.failed` / `run.cancelled` | 沿用 Run 终态及错误；启动失败即使没有 Session 也可展示 |

错误保留在所属模型、工具或 Run 事件上，避免另生成没有关联信息的重复 Error 行。允许工具失败后模型继续执行并最终成功。

## 4. 采集、保存与恢复

1. 在现有业务插件内增加小型 Trace adapter，只观察平台管理的 Session。利用 `agent/assistant-stream` 的 start 通知，在 Session 追加 `platform/trace-model-start` 扩展事件，保存当时的实际路由和 turn/step。事件不进入模型上下文，按现有机制设为 ignorable，使未知该扩展的读取端能跳过。
2. 成功结果、失败 attempt、工具结果和重试直接消费既有持久化事件；不保存每个流式 token 的独立 Trace 行，不复制完整 stream。核对 thrown error / abandoned 分支；确实没有持久化错误详情时，通过现有错误 hook 补一条有来源关联的事件。
3. 新增 `platform_run_traces` Storage Domain，保存按 Run 分区的有界事件页、投影版本、源游标和摘要。复用现有存储路由；不引入新数据库。大参数/结果保留有界预览与原始引用，不塞进 Run 记录或列表响应。
4. 按 Run 串行消费源日志；先确保对应 Session 事件已经 flush，再落投影。写入顺序为事件页、摘要、游标；游标只在本批写入成功后推进。用确定性键覆盖重放数据；摘要从已保存事件推导或记录已应用位置，禁止重放时再次累加。未证实 Storage Domain 跨记录事务前，不假定这些写入是原子的。
5. 订阅 Run domain 变更和 Session 事件，初始化时对账遗漏。终态 Run 也可能有尚未完成的 Trace 投影，不能仅恢复 RUNNING Run。按投影游标与源数据补齐，普通分页读取不反复重扫全量 Session。
6. Trace 失败不改写任务结果；记录明确日志并暴露 `pending / complete / partial / unavailable` 数据状态，支持从原始日志重建。关闭时先让 Run 停止并结算，再 drain Trace 写入、注销监听和关闭存储。
7. 历史 Run 在首次访问时按原始日志生成投影；缺失真实模型起始时间时展示未知，不用 step/start 或迁移时间伪造。恢复时生成的工具/turn 收尾记录与真实执行结束区分，不能显示成准确调用耗时。

新增插件事件的写入失败处理需要测试：监听器不能把 Trace 异常传播为 Agent 执行失败；同时不能静默声称记录完整。复用 Session 持久化边界，第一版不承诺进程骤停前尚未 flush 的事件零丢失。

## 5. 指标口径

- **Run 总耗时：** 继续使用 Run.startedAt 到真实 finishedAt 的墙钟时间；运行中随当前时间更新，检测到中断的历史任务保持未知。不能把模型耗时与并行工具耗时相加当作总耗时。
- **模型调用耗时：** 新调用开始事件到对应持久化结算事件，含流式输出，不含之前的上下文准备和下一次重试等待。表示 Harness 观察到的调用区间，不声称是 provider 内部计算时间。
- **工具耗时：** 同一调用的 tool/call 到 tool/result，包含该调用链内的权限或适配等待；不是远端工具纯计算时间。尚无结果时展示“执行中”；中断恢复记录展示“不完整”。
- **调用次数：** 每个真实开始的模型 attempt 计一次，重试也计入；Tool Calls 按实际 tool/call 去重计数，模型只生成但未派发的工具请求不计。旧数据只能确认已结算 attempt 时明确覆盖范围。
- **Token：** 使用 provider 返回的 usage，不按字符数冒充真实 Token。当前 Harness 的 inputTokens 是未命中缓存的输入，展示完整输入时还需纳入 cacheReadTokens/cacheWriteTokens；reasoningTokens 是输出子集，不能再次加入总数。优先复用现有精确汇总方法。
- **缺失 usage：** 单次显示未知；摘要可显示“已记录 Token”并标明部分数据，只有全部调用 usage 充分且一致时展示精确总量。stream usage 与 assistant/message.usage 是同一调用的两种记录，不能重复求和。
- **输入 Token 展示时机：** provider usage 往往在调用结束才返回，运行中无需显示虚假的精确数值。第一版可以在结果返回后补充到同一调用卡片。

## 6. API 与页面

沿用现有 Typert Remote 与 registry-client，增加两个小接口，实施时遵循仓库命名规范：

- `runTraceGet(workspaceId, agentId, runId)`：摘要、数据完整性、投影版本/修订号。
- `runTraceEvents(workspaceId, agentId, runId, cursor?, limit?)`：有界事件页及下一游标。

每次请求校验 workspace → agent → run 归属；cursor 必须绑定 Run 和投影版本，不能拿别的 Run 游标读取数据。权限沿用当前 shared-host 模型，不把此功能包装为完整 RBAC。

详情顶部保留状态、版本、总耗时，新增输入/输出/总 Token、模型调用数与工具调用数。下方按照执行顺序显示时间线，模型与工具的 start/result 在界面组合为可展开卡片；最终答案和 Run 终态独立显示。参数/结果在展开后读取必要详情，明确截断和原始记录入口。

运行中采用现有有限轮询；终态后还需等待 Trace complete，再停止轮询。若投影失败则展示 partial/unavailable 与重试入口，不无限轮询。增量数据用 eventId 去重；同一毫秒按源顺序排序，Final Answer 排在所属 Run 结束之前。滚动加载历史页时不能漏掉同时新增的尾部事件。

JSON 解析失败显示原文，所有内容以文本安全渲染。Trace 新增预览对常见凭证字段做掩码并限制体积；这不替代已有 Session 原文的权限与保留策略。完整结果沿用现有原始执行记录入口，不新增绕过 Run 归属校验的原文接口。所有文案提供中英文。

## 8. 完成标准

- 打开一个 Run，可看到完整的模型—工具—最终答案时间线；刷新或正常重启后仍可查询。
- 运行期间即可看到已开始的调用，结果到达后补齐耗时、Token 与输出。
- 工具错误、模型错误、启动失败和取消能定位到对应事件，且 Trace 不改变 Run 既有终态规则。
- 重试、并行工具、重复通知和恢复重放不会漏配结果或重复计数。
- 历史缺失、usage 缺失、投影滞后及中断恢复如实展示，不伪造精确指标。
- 事件明细不使 Run 列表响应膨胀；长 Trace 可分页；参数和结果有体积限制。
- 未实现另一套 Agent Loop，未引入独立观测基础设施；原 Run/Version 相关回归通过。
