# Agent Note: Run execution Trace

Status: implemented

English | [中文](2026-09-17-run-trace.zh.md)

## Problem

A task status does not identify failing model attempts, tool errors, growing input or the order of execution. Session logs already retain most facts, but model-attempt starts are transient and a developer needs a bounded Run-scoped query.

## Decision

[PlatformTraces](../../../../packages/business/agent-builder/src/platform-traces.ts) observes existing Harness notifications without modifying the loop. It persists actual model-start observations with the adjacent Session sequence in its own Storage Domain: Session.append does not expose an ignorable extension-event option. Settlements and content remain sourced from the original Session. The [pure projection](../../../../packages/business/agent-builder/src/trace-projection.ts) pairs tool results by call identity, retains every settled model attempt and references the Run's selected final answer.

Revisioned event pages precede their summary commit. Queries only expose published pages; a cursor crossing revisions fails explicitly. Reconciliation replaces derived accounting, so retries cannot add usage twice. Failures are logged and surfaced as partial/unavailable without changing Run status. Runtime closes before Trace drains. The first version coalesces execution notifications and folds the source log on reconciliation; ordinary reads use stored pages. It deliberately avoids a second durable incremental-state schema until long-Run cost justifies it.

## Alternatives considered

**Changing Session or the Agent Loop** to publish another durable model-start event would widen the Harness change for platform-only diagnostics. Existing transient hooks and platform persistence provide the required observation.

**Query-only Session scans** lack durable start timing and repeatedly read transcripts for the page. **An independent telemetry service** adds deployment and distributed consistency before this single-Host feature requires them.

## Consequences

The Run remains the task authority, while the Trace page explains its execution. Raw content is not duplicated into the Run index. Missing timing/usage and synthetic interruption facts remain visibly incomplete. Abrupt process loss can lose observations not yet flushed; there is no zero-loss audit guarantee or retention service. Source reconciliation is linear in the Run log and repeated projection writes use revisioned pages. A subsequent incremental implementation can preserve the public event and query format.
