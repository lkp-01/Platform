# Agent Note: Run 执行 Trace

Status: implemented

[English](2026-09-17-run-trace.md) | 中文

## 问题

任务状态无法说明失败的模型尝试、工具错误、输入增长或执行顺序。Session 日志已保存大部分事实，但模型调用起点是瞬时通知，开发者需要有界的 Run 查询。

## 决策

[PlatformTraces](../../../../packages/business/agent-builder/src/platform-traces.ts) 观察已有 Harness 通知，不修改执行循环。它在独立 Storage Domain 保存实际模型起点及相邻 Session 序号：Session.append 未提供 ignorable 扩展事件选项。结算与内容仍来自原始 Session。[纯投影器](../../../../packages/business/agent-builder/src/trace-projection.ts) 按调用标识配对工具结果，保留每次已结算模型尝试，并引用 Run 选定的最终答案。

版本化事件页先落盘，再提交摘要。查询仅暴露已发布页面；跨版本游标明确失败。对账替换派生统计，因此重试不会重复累计用量。失败写入日志并显示为部分数据/不可用，不改变 Run 状态。Runtime 先关闭，再排空 Trace。第一版合并执行通知，在对账时折叠源日志；普通读取使用已保存页面。在长 Run 成本需要优化前，不增加第二套持久化增量状态 Schema。

## 考虑过的替代方案

**修改 Session 或 Agent Loop** 发布另一种持久化模型起点，会为平台诊断扩大 Harness 改动。已有瞬时钩子与平台存储能提供所需观察。

**仅在查询时扫描 Session** 缺少持久化调用起点，且页面反复读取对话。**独立遥测服务** 在单 Host 功能需要之前就引入部署和分布式一致性。

## 影响

Run 仍是任务状态权威，Trace 页面解释执行过程。原始内容不复制进 Run 索引。缺失时间/用量及合成的中断事实明确标为不完整。进程骤停可能丢失尚未 flush 的观察；不提供零丢失审计或保留服务。源对账计算量随 Run 日志长度增长，重复投影写入使用版本化页面。后续增量实现可保留公开事件和查询格式。
